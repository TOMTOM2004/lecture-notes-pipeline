## 変換直後: converted/pdf_md の構造整形（必須）

`scripts/pdf/convert-pdf.py` 実行後、生成された `courses/{course}/converted/pdf_md/L{NUM}_*.md` を
**その場で** 整形する。これは PDF→Markdown 変換の一部であり、図処理（Phase 0-1）やノート整形の前に行う。
`convert-pdf.py` 単体では機械的な整形（空欄→`（ **** ）`、日本語文字間・和文記号隣接の謎スペース除去）
のみ行われるため、構造（見出し・段落分断・文中改行・数式復元）の修正はこの LLM パスで補う。**再変換時は convert-pdf.py と
このパスを必ずセットで実行する**（スクリプト単体再実行では見出しがフラットに戻る）。

### 整形ルール

1. **ページ跨ぎで割れた語・文の再結合**
   opendataloader はページ区切り直後の断片を見出し（`#`/`##`/`###`）に誤判定することがある。
   見出し行の直前の非空行が文末記号（`。 ． ） 」 』` 等）で終わっていない場合、それは文の途中の
   分断 → `#` を外して前の段落へ結合する（日本語は語の連結なので空白を入れない）。
   - 例: 直前段落末「…設備投資，研究開」＋ `## 発費など）…` → 「…設備投資，研究開発費など）…」
   - 文書冒頭の主題行に付いた `#`（正規のタイトル）は demote しない。直前行の有無ではなく
     「割れた語/文か」で判定する。

2. **本文に埋もれた章タイトルの見出し化**
   配布資料の節タイトルが本文段落として出力されることがある。文書のアウトラインに沿って
   見出しレベルを与える。H1→H2→H3 の階層を飛ばさない。
   - 章番号付き（`１ ○○`，`２ ○○`）→ `##`
   - 小節名（`売上高`，`営業利益` 等の独立した短い見出し行）→ `###`
   - 枝番（`（１） ○○`，`（２） ○○`）→ `####`

3. **穴埋め表記の維持**
   空欄は変換スクリプトが `（ **** ）`（`****` の前後は半角空白）に正規化済み。そのまま維持し、
   空白に戻したり数を変えたりしない。図表内の構成割合欄 `（ **** %）` も同様。

4. **文中改行（ソフトラップ）の結合**
   PDF の見た目の行折り返しがそのまま `\n` として出力され、1 つの文が途中で改行されることがある。
   文末記号（`。 ． ！ ？ 」 』`）で終わっていない本文行が、次の本文行へ続いている場合は 1 行に結合する。
   - **保持する**: 段落境界（空行 `\n\n`）・箇条書き（`-`）・表（`|...|`）。これらは意図的な改行なので結合しない。
   - 結合時、日本語どうしの境界は空白を入れず連結。英数字どうしの境界は半角空白 1 個を残す。
   - **数式は別扱い**: opendataloader は分数・計算式を複数行や語の羅列（例: `有形固定資産 平均従業員数 = …`）に
     分解しがちで、スクリプトの謎スペース除去で分子／分母が連結することもある。本文の数式は文脈から
     分数・等式を復元し、`分子<br>―――<br>分母` 形式（語の区切りは全角空白）で整形する。

5. **謎スペースの最終確認（バックストップ）**
   日本語文字間・和文記号（`「」『』（）、。，．` 等）隣接の半角スペースは変換スクリプトが
   機械的に除去済み。残りがあれば和文として不要なものを除去する（例: `の 「営業`→`の「営業`）。
   ただし `（ **** ）` の内側スペースは穴埋めマーカーなので除去しない。英数字に隣接するスペース
   （`S 社`，`次の 2 つ`）は意図的な組版なので残す。

## Phase 0: PDF種別の判定

1. `courses/{course}/converted/pdf_md/L{NUM}_*.md` を読み込む
2. MD内の `![image N]` 参照数と総行数をカウントし、比率を計算する
3. 判定:
   - **比率 < 5%** → テキストPDF（ドキュメント型）: **Phase 1 をスキップ**して Phase 2 へ
   - **比率 >= 5%** → スライドPDF: **Phase 1 を実行**

## Phase 1: 画像の判別とテキスト化（スライドPDFのみ）

### 1. PDFページ画像の事前生成

```bash
mkdir -p .tmp_inspect/{lecture}_pages
pdftoppm -png -r 150 "courses/{course}/raw/handouts/pdf/L{NUM}_*.pdf" .tmp_inspect/{lecture}_pages/page
```

> Claude CodeのReadツールはPDFを直接開けないため、poppler（pdftoppm）でPNGに変換する。

### 2. 全ページの確認

生成された全PNG（`page-01.png` 〜 `page-NN.png`）を `Read` ツールで読んで、各ページの内容を把握する。
ページ数が30を超える場合は分割して読む。

### 3. 画像の分類と処理

各 `![image N](...)` 参照について、対応するページを見て以下のどれに該当するか判定する:

| 分類 | 判定基準 | 処理 |
|---|---|---|
| **concept-diagram** | 矢印・箱・関係図・フロー図など、構造的に意味を持つ図 | **残してテキスト化**（下記フォーマット） |
| **theory-chart** | 軸と曲線で理論を示す図（フィリップス曲線・需給曲線・テイラー・カーブ等） | **残してテキスト化**（下記フォーマット） |
| **data-chart** | 実データの時系列・棒グラフ・散布図 | **残して概形を1〜2文で記述** |
| **photo** | 写真・人物肖像・建物・紙幣現物・歴史画像 | **参照行を削除** |
| **decorative** | 章扉（セクション区切り）・ロゴ・装飾 | **参照行を削除** |

**判断原則**: 「文字で説明することで内容理解に付加価値があるか」。写真・章扉は説明しても付加価値がないため削除する。

### 4. テキスト化のフォーマット

**concept-diagram**:
```markdown
> **図: [簡潔なタイトル]**
>
> [構造の説明: 配置・矢印の方向・ラベル]
>
> - [要素1の説明]
> - [要素2の説明]
>
> [図全体の含意・結論]
```

**theory-chart**:
```markdown
> **図: [グラフのタイトル]**
>
> 縦軸=[ラベル]、横軸=[ラベル]。
> - [曲線1の形状・意味]
> - [曲線2の形状・意味]
>
> [理論的含意]
```

**data-chart**:
```markdown
> **グラフ: [タイトル]**
> [概形を1〜2文で。例: 「1990年代から2010年代まで低下し、2020年以降上昇」]
```

> 出典（著者・書名・ページ番号等）は省略してよい。本文中に既に言及がある場合は特に不要。

### 5. 後処理

- 処理完了後、`.tmp_inspect/{lecture}_pages/` を削除する
